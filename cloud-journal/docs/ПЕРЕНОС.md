# Перенос существующего журнала

1. Завершите работу в Windows-программе. Скопируйте целиком папку с `journal.json` и вложениями в резервное место. Копию не изменяйте.
2. Откройте облачный сайт на компьютере, войдите администратором и выберите «Перенос».
3. Выберите всю папку данных. Если нужен только журнал без медиа, выберите отдельно `journal.json`. Папка должна содержать один основной `journal.json`; резервные копии `.bak` не используются.
4. Нажмите «Проверить перенос». Сайт покажет новые, уже совпадающие и конфликтующие заявки, количество вложений. При конфликте записи с одинаковым ID не заменяются.
5. Нажмите «Перенести заявки и вложения». Записи сохраняются одной транзакцией. Вложения идут следом, частями, с проверкой SHA-256 из локального журнала. Не закрывайте вкладку во время загрузки.
6. Сверьте количество заявок, несколько дат, СДУ, итог простоя и доступность фото / видео. Включите MAX по инструкции Render и создайте учётные записи сотрудников.
7. С этого момента работайте по ссылке сайта и с компьютера, и с телефона. Старая программа не получает облачные изменения автоматически.

Сохраняются идентификаторы, все исходные даты и заполненные поля, отметка СДУ. Событие «Перенос из Windows» содержит администратора и фактическое время импорта. Исторический автор сохранения каждого старого этапа неизвестен, поэтому выдуманные авторы и серверные даты не создаются; фамилии из старого журнала остаются в исходных полях.

Один перенос — до 3000 заявок и до 32 МБ JSON. Для большего журнала нужен подготовленный пакетный перенос; не обрезайте исходный файл вручную. В браузере также требуется место для хранения неподтверждённой команды.

Файлы ищутся по сохранённым именам из `Attachments`. Их размер и контрольная сумма должны совпадать. Отсутствующие файлы будут перечислены. TIFF не импортируется автоматически: преобразуйте его в JPG и добавьте к нужной заявке отдельно после переноса. Новое ручное добавление при включённом MAX отправляет сообщение в группу.

При обрыве связи снова выберите тот же файл / ту же папку в той же вкладке. Жёлтый блок позволяет подтвердить неизвестный результат прежней команды. Успешно перенесённые записи не дублируются, одинаковые файлы определяются по SHA-256. Если после переноса в облаке уже добавлялись новые этапы, исходный журнал будет конфликтовать; для оставшихся файлов используйте «Перенести только вложения», когда все ID заявок уже есть на сервере.

Старые уведомления MAX, токены и `max-settings.json` не загружаются. Вложение при переносе сохраняется без отправки в чат. Статус старой локальной очереди не переносится; если в ней остались сообщения, решите их судьбу до окончательного отключения локальной программы, чтобы потом не запустить старую рассылку случайно.

Старые заявки без номера цеха будут доступны только администратору. Приложение сохраняет их исходные данные, но не предоставляет произвольное исправление уже зарегистрированных сведений.
