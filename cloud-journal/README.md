# Журнал ремонта кранов — облачная версия 2.0

ASP.NET Core 10, ASP.NET Core Identity, PostgreSQL 17 и адаптивный интерфейс на русском языке. Исходная локальная Windows-версия не изменяется. Компьютер и телефон работают с общей базой через браузер; постоянно включённый рабочий компьютер не нужен.

**Статус пакета:** исходники и конфигурация подготовлены; сайт не опубликован. JavaScript-проверки выполнены, сборка C# и серверные проверки в этой среде недоступны. Перед рабочим запуском выполните проверки из [VERIFICATION.md](VERIFICATION.md).

## Работа с журналом

- Администратор создаёт личные учётные записи и назначает цеха. Роли: администратор, сотрудник с правом записи, просмотр. Саморегистрации нет. Временный пароль нужно сменить при первом входе.
- Этапы идут последовательно: регистрация → реагирование → выдача в ремонт → выдача из ремонта. При закрытии обязательно описание устранения.
- Даты этапов можно указать для уже произошедшего события. Если поле пусто, берётся текущее время предприятия. Отдельно сервер фиксирует фактическое время сохранения в UTC и автора. В интерфейсе оно переводится в часовой пояс предприятия.
- Сохранённые даты и заполненные описания не перезаписываются. Удаление заявок через приложение отсутствует. История и результаты команд дополнительно защищены триггерами БД от UPDATE / DELETE. Это защита приложения, а не от владельца самой БД.
- Повтор команды с тем же `commandId` возвращает её прежний результат. Другой сотрудник или другой текст с тем же идентификатором получают конфликт. Изменение со старой `expectedRevision` отклоняется.
- Отметка «Работа с СДУ с ограничениями» доступна и после закрытия. Расчётная длительность остаётся видимой и зачёркивается; в общий итог идёт ноль. Смена отметки также записывается в историю.
- Фото / видео хранятся в PostgreSQL частями по 2 МиБ. Перезапуск веб-сервиса не удаляет их. Загрузка продолжается при повторном выборе того же файла в той же вкладке; незавершённые загрузки удаляются через 24 часа. Одинаковое содержимое повторно к той же заявке не добавляется.
- Итоги относятся к текущему фильтру и времени последнего обновления. CSV открывается в Excel и содержит СДУ и имена вложений. CSV не является полной резервной копией.

## Расчёт простоя

Для завершённой заявки с полными этапами:

```
Простой = (выдача из ремонта − регистрация)
          − (выдача в ремонт − реагирование)
```

Например, регистрация 08:00, реагирование 09:00, выдача в ремонт 11:00, из ремонта 13:00: **3 часа**. При СДУ показывается зачёркнутое «3 ч 00 мин», в сумме — ноль.

У открытой заявки после реагирования ожидание исключается до текущего момента. У старой завершённой записи без одного из необходимых этапов вычет неизвестен, поэтому сохраняется полный период. Часовой пояс по умолчанию `Europe/Moscow`; менять его после начала ведения журнала без согласованного переноса времён нельзя.

## MAX

Сервер отправляет сообщения в указанную общую группу на каждом новом этапе, при изменении СДУ и добавлении файла. При закрытии сообщаются выполненные работы и расчёт простоя. Новые уведомления создаются, только когда заданы `MAX_BOT_TOKEN` и `MAX_CHAT_ID`; задним числом старые этапы автоматически не рассылаются.

Очередь хранится вместе с событием в одной транзакции. Недоступность MAX не отменяет сохранение заявки. Ошибки подключения, ограничения частоты и незавершённая обработка вложения допускают повтор. Когда MAX мог уже принять сообщение, автоматический повтор останавливается: администратор проверяет группу и выбирает повтор либо отмену. Абсолютно однократную доставку во внешний MAX при потерянном ответе гарантировать нельзя.

В разделе MAX видны проверка подключения и первые 200 незавершённых отправок, начиная со старых; «История» показывает последние 200 уведомлений. Вложения, добавленные при отключённом MAX или перенесённые из старого журнала, можно отправить вручную из карточки.

Поддерживаются JPG, PNG, GIF, BMP до 50 МБ и 7680×7680, MP4, MOV, MKV, WEBM до 250 МБ. Перед загрузкой проверяются расширение, размер, сигнатура и размеры фото; декодирование медиа выполняет MAX. HEIC / TIFF преобразуйте в JPG. Большой файл также должен помещаться в общую квоту хранилища.

## Локальная проверка разработчиком

Нужны Docker с Compose либо SDK .NET 10 и PostgreSQL 17. Команды выполняются из корня этого проекта.

```sh
docker compose --profile checks run --build --rm checks
```

Проверки используют только отдельную временную БД `crane_journal_checks` и не отправляют сообщения в MAX. Для запуска интерфейса скопируйте `.env.example` в `.env`, задайте собственные пароли (без точки с запятой в пароле БД для этого примера строки подключения) и выполните:

```sh
docker compose up --build -d web
```

Откройте `http://localhost:8080`, войдите как `admin` с паролем из `.env`, смените пароль. Этот Compose настроен только для локальной проверки: HTTP слушает `127.0.0.1`. Для доступа из интернета применяется Production с HTTPS и конфигурацией Render.

## Состав

`src/CraneJournal.Shared` — расчёт, правила журнала, CSV и клиент MAX; `src/CraneJournal.Web` — сервер, Identity, PostgreSQL, очередь и интерфейс; `checks` — проверки клиента, доменных правил, БД и реального HTTP-приложения. Dockerfile собирает сервер и выполняет доменные проверки. `.gitlab-ci.yml` выполняет клиентские и полные серверные проверки в отдельной тестовой БД.
