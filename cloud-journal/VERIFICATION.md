# Статус проверки пакета

Дата подготовки: 01.10.2026. Это отчёт о выполненных действиях, а не утверждение об успешном рабочем развёртывании.

## Выполнено в текущей среде

- `node --check` для `app.mjs` и `ui.mjs`: успешно.
- `node --test checks/ui.test.mjs`: **8 проверок, все пройдены**. Включены формат длительности свыше суток, отсутствие смещения местных дат, экранирование текста, последовательность этапов, перенос СДУ без секретов и старой очереди, отказ от небезопасных имён вложений, поведение реального JS-клиента при потере / обрыве ответа и повторном нажатии.
- XML проектов, JSON манифеста, синтаксис YAML конфигураций и ссылки на статические файлы проверены при упаковке.

Проверка клиента использует небольшие подставные DOM и API. Она не заменяет проверку в настоящем браузере или серверные тесты.

## Не выполнено в этой среде

- Сборка ASP.NET Core 10, доменные C#-проверки, PostgreSQL / HTTP интеграционные проверки и сборка Docker-образа. Доступен лишь SDK 8, который к тому же завершается до загрузки проекта: `Failed to create CoreCLR, HRESULT: 0x8007000E`. Docker и PostgreSQL здесь отсутствуют.
- Визуальная проверка в Chromium: библиотека Playwright имеется, исполняемый файл браузера отсутствует.
- Публикация Render и отправка настоящих сообщений в MAX. Пользователь подтвердил рабочее пространство Render и загрузку в подключённый репозиторий GitHub. Загрузка исходников пока не завершена, сервис и БД не созданы; секреты MAX не предоставлены.

## Обязательные проверки перед рабочим запуском

Из корня проекта:

```sh
node --test checks/ui.test.mjs
docker compose --profile checks run --build --rm checks
```

Второй вызов собирает проект, выполняет доменные проверки и затем проверки на отдельной PostgreSQL с реальным HTTP-приложением. Они охватывают идемпотентность, конкурентное реагирование двух сотрудников, запрет чужого цеха и записи для роли просмотра, неизменяемость истории, части файлов и SHA-256, повторную загрузку, импорт без MAX, аренду очереди после перезапуска, cookies, CSRF, историю автора и выход из сеанса.

Тесты удаляют и создают заново **только специально выделенную БД `crane_journal_checks`**. Конфигурация Compose содержит для неё отдельный временный контейнер. Не направляйте её в рабочую базу. Реальный клиент MAX во время проверок не запускается.

Если Docker не используется, нужны SDK .NET 10 и отдельная PostgreSQL 17. Задайте `CHECK_DATABASE_URL` для `crane_journal_checks` и выполните из корня:

```sh
dotnet run --project checks/CraneJournal.Checks.csproj -c Release -- --integration
```

Для текущего размещения в подпапке репозитория проверки подготовлены в `../.github/workflows/cloud-journal.yml`; GitHub Actions пока не запускались. `.gitlab-ci.yml` сохранён для отдельного размещения проекта в GitLab. Dockerfile останавливает сборку при ошибке компиляции или доменных тестов; он не заменяет отдельные интеграционные проверки с БД.

После успешной сборки проверьте сайт на реальном телефоне: вход и смена пароля; две одновременные попытки сохранить один этап; правильный вычет ожидания; СДУ и суммарный простой; фото, видео и обрыв загрузки. Затем подключите MAX и проверьте сообщения в выбранной общей группе. До этого не заменяйте единственный рабочий журнал новой системой.
